2. The critical path — "cite-or-abstain" grounding pipeline

This is the hardest engineering problem and the core of the architecture: guaranteeing that no ungrounded claim reaches the user. Grounding is enforced mechanically (verifier rejects any output whose quote doesn't match the source), not merely requested in a prompt.

flowchart LR
  A["Raw document"] --> B["Span-anchored ingestion
char offset + page + bbox"]
  B --> C["Clause segmentation
+ classification"]
  C --> D["Scoped retrieval
(RAG over this doc + reg KB)"]
  D --> E["Constrained extraction
JSON + verbatim quote + offsets"]
  E --> F{"String-match
verifier"}
  F -- "quote not found" --> X["Reject / abstain"]
  F -- "match" --> G{"Entailment check
(NLI critic)"}
  G -- "not entailed" --> X
  G -- "entailed" --> H["Calibrated confidence
logprob + retrieval + NLI + ensemble"]
  H --> I["Finding
clause ref · severity · rationale · suggested wording"]
  I --> J["Human-in-the-loop review
→ feedback + audit log"]

4. Design principles that map to the evaluation metrics

  • Extraction accuracy & risk precision → span-anchored ingestion + verifier reject loop + gold-labeled eval harness (F1, precision/recall).
  • Explainability → every finding carries clause reference, confidence, rationale, cross-reference link, and suggested wording by construction.
  • Compliance validation → rules run over structured, grounded facts and a clause↔regulation knowledge graph, so findings inherit traceability.
  • Scalability & latency → stateless FastAPI services, async worker queue for ingestion/analysis, pgvector for retrieval, horizontal scale-out.
  • Enterprise security → RBAC at the gateway, encrypted object storage, row-level security in Supabase, immutable audit logging.
  • Production readiness → API-first contracts, eval-gated releases, human-in-the-loop with feedback capture.
